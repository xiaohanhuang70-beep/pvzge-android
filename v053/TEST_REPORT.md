## 验证方式的边界

1. **自动化输入测试**：运行实际适配脚本，检查事件顺序、取消、多指、按键释放、菜单、防重复、状态变化门槛。
2. **游戏函数契约测试**：从最终 APK 使用的 `assets/main/index.js` 提取实际函数执行。场景服务、动画和对象依赖受控；不能把这类测试写成完整游戏运行通过。
3. **实际运行测试**：CI 用 Chromium、触摸输入和 SwiftShader 启动完整游戏资源，通过真实 Cocos 场景组件读取交互结果。浏览器为桌面 Chromium 触摸模拟，未指定 Android UA，不是 Android WebView、模拟器或手机。
4. **安卓真机**：本轮没有连接安卓设备，没有安装或操作用户手机。下表所有真机栏均为待验证。

静态审计覆盖了游戏内 32 个显式使用鼠标/触摸事件常量的模块，包括地图、世界选择器、商店、图鉴、选卡、奖励、小游戏、花园、战斗 UI、MouseBlocker 和 PauseScreen。它不是“所有功能已验证”的证明。

## 测试结果与排错记录

自动化：37 项输入回归、10 项实际游戏函数契约、12 项上游 Node 回归，共 59 项通过。另有 RenderSize、UpdateVersion 两项 Java 回归通过。

完整资源运行：共 11 项，10 项通过、1 项未通过（单指切世界）。该运行步骤允许 APK 编译继续，故不得用 Actions 总体绿色替代逐项结果。

- 最初 ZIP 的 15 个模拟测试通过，但没有覆盖本轮关键回归；本分支改为更完整的输入套件。
- 新测试先复现了设置识别优先级、真实 Node `_components`、取消后的延迟点击、切场景残留、真实卡片选择/铲除状态门槛、世界切换等缺口，再修改适配层。
- 完整运行发现“设置原生单指拖动没有改变偏移，双指滚轮有效”，因此取消了只依赖原生 ScrollView 拖动的方案，改为有纵向意图后取消原生按压并生成滚轮；轻触和横向滑块保留原生。
- 完整运行读取了花园原有工具选择状态及相机 scale/pos，未仅凭 DOM 事件生成就写成已实现。
- 对话改为读取 CurrentFlow/CurrentFlowStep 和可见台词状态，再调用原游戏 RunFlow；不让同次对话触摸误触世界卡片的进入状态。普通事件路线已推进剧情时不重复调用。
- 世界横滑比较真实 WorldMapChooser.currentI，滚轮未生效才调用原有 moveBy；原生触摸或滚轮已改变索引时不重复切换。
- 早期运行脚本曾因异步 `waitForFunction` 谓词错误提前继续，后改为同步检查。早期输出不计入最终运行验收。

完整运行日志未捕获脚本异常（errors 数组为空），但单指切世界断言失败，仍按未通过记录。

## 已知问题与潜在风险

- **已知未通过：单指切世界。** 真实场景回归中索引仍为 0。当前未确认是输入路径、游戏切换时序还是测试准备因素；本轮不计入修复完成，也不反复重做该项检查。

- 本版仍是原生 Cocos 触摸与桌面事件共存的兼容层，没有重写全部游戏状态机，也不能宣布所有界面已全面修复。
- Chromium 运行与 Android WebView 的输入、UA、DPI、帧率和多指取消行为可能不同；真实手机的重复触发、坐标映射、滚动手感和全屏恢复需要回归。
- 设置纵向划动有 12 像素方向阈值；触摸初始位置落在滑块或特殊控件上时，仍需检查是否误改选项。
- 双指起手前，第一根手指的原生 TOUCH_START 可能已产生游戏自身的即时反馈；取消不能回滚已发生的业务操作。
- 新存档缺少花园植物；没有用伪造的植物管理成功结果替代实际测试。
- Original 渲染选项保留，但未测量手机 GPU、内存、发热或长期帧率。
- 此为 CI debug 签名包；后续重编译的签名不保证一致，不应把它当作稳定版原位升级渠道。不要为安装测试包而卸载有存档的版本。
